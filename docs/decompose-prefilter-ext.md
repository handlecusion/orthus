# decompose 프리필터 신호 확장 (O4/E3)

> 상태: 구현(플래그 fail-closed, default off) · 2026-07-13
> 실험 계획서: `experiments/fugu-ko/analysis/e3-decompose-prefilter-plan.md`
> 측정 스크립트: `experiments/fugu-ko/e3_prefilter.py` · 골든: `golden/e3_missed.json`, `golden/e3_control.json`

## 1. 문제 (O4)

`should_decompose`는 2단이다 — **stage 1 결정론 프리필터**(LLM 0회)가 통과시킨 질문만
**stage 2 LLM 게이트**로 간다. 그런데 stage 1이 아는 신호는

- 명령 verb `_COMMAND_VERBS` (해줘/정리/작성/보내 …),
- 접속어 `_CONNECTIVE_TOKENS` 7개 (그리고/그다음/또한/동시에/그후/알려주고/해주고),
- 열거 `_ENUM_TOKENS` 5개 (①②③/첫째/둘째) + `"1."`&`"2."`

뿐이다. 그래서 **"랑/이랑/각각/비교/와·과" 형태의 복합질문은 LLM 게이트에 도달조차 못 하고**
단일로 답해진다. 사용자에겐 "물어본 것의 절반이 조용히 사라지는" 실패로 보이고, **모델을
교체해도 사라지지 않는다**(모델 이전 단계의 결정론 코드에서 잘린다).

실측(2026-07-13, `e3_prefilter.py`): 누락형 골든 40문항의 **tier 0 프리필터 도달률 = 0/40**.
기존 t7 골든에도 이미 이 형태가 있다 — 예: t7-02 "아크메 직원 수**랑** 아틀라스 프로젝트 상태를
같이 알려줘"(compound=true)는 지금 게이트에 도달하지 못한다.

## 2. 제약: 공유 토큰셋 (최대 리스크)

`_has_connective_or_enum`은 **세 모집단**이 함께 읽는다.

| 소비자 | 용도 |
|---|---|
| `should_decompose` | 복합질문 분해 게이트 진입 |
| `command_split_signal` | command-split 진입 (agent_work 라우트) |
| `mail_has_orchestration_signal` | event-orch 메일 트리거 |

상수를 직접 늘리면 세 모집단이 한꺼번에 오염된다(= flag-off byte-identical 파괴).

## 3. 설계

확장분은 **별도 티어 테이블**(`_PREFILTER_EXT_TIERS`)로 두고, `_has_connective_or_enum`에
`ext_tier` 키워드(default 0)를 추가한다. **`should_decompose`만** 설정 티어를 넘긴다.
`command_split_signal` / `mail_has_orchestration_signal`은 인자를 넘기지 않으므로 default 0 —
두 모집단은 티어와 무관하게 불변이다(단위 테스트 `TestPopulationIsolation`이 고정).

티어는 **단일 질문에서의 출현 빈도(= FP 위험) 순**이며 누적 적용된다.

| 티어 | 신호 | FP 위험 |
|---|---|---|
| T1 | 각각 · 비교 · 차이 · vs · 둘 다 · 모두 알려 · 셋째 · ④ | 낮음 (단일 질문에 드묾) |
| T2 | 이랑 · `"랑 "` · 뭐고 · 이고 | 중간 (조사·연결어미라 단일에도 출현) |
| T3 | `"와 "` · `"과 "` (병렬 조사) | 높음 — "A와 B의 관계는?"(단일)과 어휘로 구분 불가 |

`"랑 "`/`"와 "`/`"과 "`는 공백에 의존하므로 원문 매칭이다(compact는 공백을 지워
"사랑"의 "랑"과 구분되지 않는다). 그럼에도 T3는 `"결과 "`/`"성과 "`가 `"과 "`를 포함하는
**어휘적 오검출**을 구조적으로 안는다 — 형태소 분석 없이는 피할 수 없고, 그래서 고위험이다.

**설정:** `ORTHUS_DECOMPOSE_PREFILTER_EXT_TIER` (int, default **0 = off**).
0이면 세 경로 모두 기존과 byte-identical. 값은 `[0, 3]`으로 clamp된다 — 오설정이 프리필터를
전부 통과시키지 않는다.

계획서(§4.1)는 bool flag였지만, §4.2가 요구하는 **티어 누적 곡선**(T1 → T1+T2 → T1+T2+T3)을
데이터로 판정하려면 티어 정수가 필요하다. 0=off라 fail-closed 성질은 동일하다.

## 4. 비용 구조 (판정의 핵심)

프리필터 오통과의 실비용은 **두 단계로 갈린다.**

1. **프리필터 오통과** → LLM 게이트 1콜 추가 = **지연 비용**. 답은 안 바뀐다.
2. **최종 오분해** → 게이트가 yes로 오판하고 실제 fan-out = **품질 비용**.

LLM 게이트가 뒤에서 FP를 거르는 구조이므로 ①이 곧 ②가 아니다. E3는 두 값을 분리 측정한다.

## 5. 측정 (§5 사전 고정 판정 기준)

- 누락형 프리필터 recall ≥ 80%
- adversarial 대조군 **최종 오분해율** ≤ 5%
- **자연 분포** 대조군 프리필터 오통과 증분 ≤ 15%p
  (adversarial 대조군은 40문항 중 28개가 함정인 **의도된 최악치**라, 그 위의 오통과율은
  실트래픽 지연 비용이 아니라 상계다. 실비용은 저작 개입이 없는 기존 t5/t7 단일 질문에서 잰다.)
- 기존 t7 골든 22문항 최종 판정 무변화
- flag off(tier 0)에서 decompose 관련 전 테스트 무변화

결과는 §7에 기록한다.

## 6. 스코프 밖

`command_split_signal` 의미 변경, LLM 게이트 프롬프트, split/synthesize 로직, `_COMMAND_VERBS`
확장, 형태소 분석기 도입(계획서 옵션 C — T3 실패 시 재검토).

## 7. 실측 결과 (2026-07-13)

골든: 누락형 40 + adversarial 대조군 40 + 자연 분포 대조군 27(t5 22 + t7 단일 5).
게이트 모델: solar-pro(변인 통제) / gpt-4o-mini(프로덕션 기본 모델 교차검증).
재현: `python experiments/fugu-ko/e3_prefilter.py --model solar|prod`.

**기저(tier 0):** 누락형 40문항의 프리필터 도달 **0/40**. O4를 그대로 재현한다 — 이 40개
복합질문은 지금 LLM 게이트를 보지도 못하고 단일로 답해진다.

| 티어 | 누락형 recall(프리필터) | 누락형 실제 분해 | 자연 오통과(증분) | adversarial 최종 오분해 |
|---|---|---|---|---|
| T0 (현행) | 0.0% | 0.0% | 7.4% (기저) | 0.0% |
| T1 | 32.5% | 30.0% | 7.4% (+0.0%p) | 0.0% |
| T2 | 67.5% | 62.5% | 7.4% (+0.0%p) | 0.0% |
| **T3 (채택)** | **100.0%** | **92.5%** | **7.4% (+0.0%p)** | **0.0%** |

프로덕션 모델(gpt-4o-mini) 교차검증: recall 100% · 실제 분해 97.5% · 자연 오통과 +0.0%p ·
자연 오분해 0.0% · adversarial 오분해 5.0%(2/40, 상한 이내). 두 오분해는 모두
"nova **vs** 경쟁 서비스 비교 자료", "슬랙 채널**이랑** 노션 페이지 **중** 어디" — 사람도
복합으로 볼 수 있는 **선택형 경계 문항**이고, 자연 분포에서는 한 건도 나오지 않았다.

**§5 판정: T3 채택** (누적이므로 T1+T2+T3 전부 활성 = `ORTHUS_DECOMPOSE_PREFILTER_EXT_TIER=3`).
T1/T2 단독은 recall 미달로 기각 — 다만 이는 티어 토큰의 결함이 아니라 골든의 유형 구성비
때문이다(각 티어는 자기 유형을 100% 회수한다). 80% 상한은 병렬 조사(T3)를 켜야만 넘는다.

**핵심 발견 — FP의 실비용은 지연뿐이고 품질 비용은 0이다.** adversarial 대조군 40문항 중
25개가 프리필터를 통과했지만(최악치 62.5%), **LLM 게이트가 전부 걸러 실제 fan-out은 0건**
(solar). 즉 프리필터 확장의 위험은 "잘못 분해된 답"이 아니라 "게이트 1콜만큼의 지연"이다.

**실측 기반 좁히기(측정 → 개선 → 재측정).** 1차 측정에서 T3는 자연 트래픽에 +22.2%p를
흘렸고, 그 6건이 **전부 관계형 질문**("A와 B는 무슨 관계야?", "nova와 연결된 문서")이었다 —
KG graph 라우트 모집단이지 병렬 나열이 아니다. 그래서 **병렬 조사 + 관계어(관계/연결/연관/
사이) → 미발화** 억제(LLM 0회)를 넣었고, 자연 오통과 증분이 **+22.2%p → +0.0%p**가 되면서
recall 100%는 유지됐다. 억제어에서 "관련"은 뺐다 — 회사 고유명사 "AI관련툴"과 충돌해
누락형 1건을 잃었기 때문이다.

**t7 회귀(22문항):** 판정 4건 변화 — `t7-02`, `t7-07`, `t7-09`, `t7-10`. **전부 False→True
개선**이며 넷 다 golden label이 `compound=true`다(gate_correct 15/22 → 19/22).
§5의 "판정 무변화" 조건은 문자적으로는 깨졌지만, 그 조건의 의도(회귀 방지)는 충족한다 —
**기존 t7 골든 안에 이미 O4 누락형이 4건 들어 있었다**는 사실이 오히려 O4의 추가 증거다.
(예: t7-02 "아크메 직원 수**랑** 아틀라스 프로젝트 상태를 같이 알려줘".)

### orchestrator e2e (실서버, 회사 스냅샷 — 2026-07-13)

같은 워크트리 코드로 API 두 벌(tier 0 / tier 3)을 company 노드 DB(위키 12,144p / 문서
2,480)에 붙여 `POST /agent-work/chats/{id}/orchestrate`로 같은 질문을 던진 A/B다.

| 질문 | tier 0 (현행) | tier 3 |
|---|---|---|
| "협업업무표 상태별 개수**와** 담당자별 개수 알려줘" | `structured` 1콜 — **상태별 개수만 답하고 담당자별 개수는 조용히 사라짐** | `decomposed` 2조각 — 상태별(시작 전 7 / 완료 771 / 보류 16) **+ 담당자별** 둘 다 답함 |
| "아크메 직원 수**랑** 아틀라스 프로젝트 상태 알려줘" | `structured` 1콜 — `[[3, None]]`(두 번째 컬럼이 `None`) | `decomposed` 2조각 — "직원 수 3명" + "아틀라스 상태 정보 없음"(미보유를 정직하게 고지) |
| "Nova**와** 아크메는 무슨 관계야?" | `wiki` 단일 | `wiki` 단일 — **동일**(관계어 억제가 실경로에서 발화 차단) |

O4의 사용자 체감 실패("복합질문의 절반이 조용히 누락")가 실데이터에서 그대로 재현되고,
확장 티어가 그걸 닫는다는 것을 프로덕션 경로에서 확인했다.

**지연(같은 A/B, 실측):** 복합질문은 **+3.5s ~ +5.8s**(2.0→5.5s, 3.9→9.8s — 게이트 1콜 +
split 1콜 + 리프 N개 병렬 + 합성 1콜). 단일질문은 tier 0과 차이 없음(관계형 4.7→4.5s,
평범 3.5→2.4s — 노이즈 범위). 즉 **비용은 복합질문에만 붙고, 단일질문 경로는 그대로다.**

### 잔여 리스크

- **자연 분포 대조군이 27문항**으로 작다. 자연 오통과 증분 +0.0%p는 "실트래픽 지연 비용이
  0"이라는 강한 주장이 아니라 "27문항 표본에서 관측되지 않았다"는 뜻이다.
- 억제어 4개는 실측 6건에서 유도했다 — 어휘 기반이라 꼬리 유형은 남는다(계획서 옵션 C의
  형태소 분석은 여전히 보류).
- prod 모델에서 adversarial 오분해 5.0%는 **상한과 같다.** 여유가 없으므로 실트래픽 활성화
  후 오분해율을 재확인해야 한다.
