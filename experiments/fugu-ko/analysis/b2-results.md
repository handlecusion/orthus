# B2 결과 — 계약 이행 (6모델, 2026-07-22)

> 사전선언: `b2-prereg.md`. 데이터: `analysis/raw/b2_summary_6model.json` · `b2_rows_6model.jsonl`.
> 실행: 국내 3사 + gpt-4o-mini는 280문항 전량, Sonnet 4.6 280 전량, **Haiku 4.5는 C1 펜스 40문항만**
> (Bedrock 최소 사용 — 정확히 320 converse 호출). 출력 생성은 프로덕션 프롬프트를 import해 사용(`b2_run.py`).

## 0. 한 줄

**주판정(계약 분산 > 정확도 분산)은 형식적으로 성립하지 않았다** — 점추정 비율 13.9배는 강하나,
6모델로는 부트스트랩 CI가 1을 포함한다(→ 프리레그 문안대로 "주장 철회, comparable").
**그러나 서술적 증거는 명확하다:** 같은 모델의 계약 이행이 배선 한 줄로 뒤집힌다(Haiku C1 37.5%→77.5%).

## 2. 핵심 발견 — 동일 C1(펜스) surface 대조

| model | C1 strict | C1 lenient | Δ(배선 복구) |
|---|---|---|---|
| Sonnet 4.6 | 100.0% | 100.0% | — |
| gpt-4o-mini | 97.5% | 97.5% | — |
| solar | 97.5% | 97.5% | — |
| **Haiku 4.5** | **37.5%** | **77.5%** | **+40.0p** |

**이것이 B2의 논지다.** Haiku는 추론이 멀쩡한데(펜스 안의 SQL 내용은 정확) 마크다운 펜스로 감싸
프로덕션 파서에 걸린다. 펜스 스트립 한 줄(lenient)이 37.5% → 77.5%로 되살린다.
**성능을 가른 것은 추론력이 아니라 출력 계약 이행이고, 그 계약 실패는 배선으로 복구된다.**
(11모델 E2E에서 Haiku가 42.8%로 최하위였던 그 현상의 격리 재현.)

## 3. 주판정 — 형식적으로 미달 (정직 보고)

```
Var_contract = 0.01011   (5개 full-set 모델 strict: 73.2/79.3/93.6/94.3/94.6)
Var_accuracy = 0.00073   (같은 5모델 145문항 정확도: 75~81%)
ratio (점추정) = 13.9
bootstrap 10,000 seed=1234 → 95% CI [0.045, 77.0]  (1 포함)
verdict = comparable  →  프리레그 문안: "두 축의 변별력이 비슷하다 — 주장 철회"
```

**왜 점추정은 13.9인데 CI가 1을 포함하나:** 분산비 검정의 표본 단위가 **모델**이다. full-set 모델이
5개뿐이라(Haiku는 분모 불일치로 페어링 제외) 모델 단위 부트스트랩이 극히 불안정하다(degenerate 120).
**이 미달은 B0 §2의 논지 그대로다 — n(여기선 모델 수)이 구속 조건이다.** 국내 3사만으로도, 6모델로도
"동률"밖에 안 나오는 이유가 이것이며, 우위 주장에는 더 많은 모델이 필요하다.

→ **보고 원칙:** 헤드라인은 "계약 분산이 정확도 분산의 13.9배(점추정)"로 쓰되 **유의성은 주장하지 않는다.**
서술적 증거(§2 Haiku 사례)가 실질 근거다.

## 4. 타당성 경고 (사전선언 §5 준수 — 감추지 않음)

1. **exaone C4 = 0%는 순수 모델 실패가 아니다.** `email_draft_payload` surface는 프로덕션 LLM
   프롬프트가 없어(페이로드는 결정론 조립) `EmailDraftPayload.model_json_schema()`를 프롬프트에 넣었는데,
   exaone이 스키마 *디스크립터*를 값으로 복사했다(`"default":"false"` 등). **러너 아티팩트가 섞인 수치**다.
   → exaone의 79.3%는 이 40문항(C4) 때문에 눌렸다. C4 제외 시 다른 유형은 전부 100%다.
2. **Haiku의 비-C1 거부는 빈 카탈로그 탓도 있다.** `structured_compile`이 런타임에 카탈로그를
   조회하는데 골든은 질문만 고정해 `(no tables)`로 렌더된다. Haiku가 "테이블이 없다"며 거부한 응답들이
   있다 — 순수 펜스 실패와 구분해야 한다(그래서 Haiku는 C1만 헤드라인에 쓴다).
3. **A.X C6 = 0%는 진짜다.** tool-call을 아예 안 하고 산문으로 답한다 — 문서화된 "A.X tool-call 무시"
   재현. recovery +8.2p도 진짜(펜스 스트립 + C2/C4 allowlist 복구).
4. Bedrock 총 **320 converse 호출**(Sonnet 280 + Haiku 40). "최소 사용" 준수.

## 5. 결론

- **B2 헤드라인은 서술적으로 성립한다:** 프로덕션에서 성능을 가르는 축은 추론력이 아니라 출력 계약
  이행이며(Haiku C1 37.5% vs 동급 100%), 그 실패는 배선으로 복구된다(+40p).
- **형식적 주판정(분산비 유의성)은 6모델로 미달** — 정직하게 "comparable/철회"로 보고한다.
  더 많은 모델을 넣으면 점추정 13.9배가 유의해질 수 있으나, 현재 표본으로는 주장하지 않는다.
- 다음: OpenAI/Bedrock으로 모델 수를 늘리면 주판정 검정력이 오른다. 단 exaone C4 아티팩트는
  프롬프트 구성을 고쳐 재측정해야 정당하다(현재는 병기 보고).
