# E1 실험 계획서 — 검증 게이트 기반 캐스케이드 + 교차모델 투표 (test-time ensemble)

> E-시리즈 우선순위 1/5 · 작성 2026-07-13 · **상태: 완료 (2026-07-13) — 결과는
> `e1-results.md`**. 판정: **캐스케이드 채택**(골든 18/18, 합성 90.0% @ 1.05×, 손실 0) /
> 투표 미채택(89.1% @ 2.15× — 상관 오류에 취약).
> 실행 위치: `.worktrees/fugu-ko-experiment` (본 워크트리, 실험 격리 유지)
>
> **계획 대비 변경 1건(실행 중 확정):** Phase B를 "골든 라이브 재실행"이 아니라 **합성 test
> structured 63문항 재실행(rows 확보)** 으로 좁혔다. 이유: `labels_*.jsonl`이 rows를 저장하지
> 않아 골든에서 회수를 만든 `zero_answer` 트리거를 합성 분포에서 재현할 수 없었고, 합성이
> (c)가 (b)를 이긴 유일한 분포라 판정이 거기서 나기 때문. §4-5의 self-consistency arm(temp>0)은
> **결정성 프로브로 대체** — temperature=0에서 이미 비결정적임이 밝혀져(TS15) arm의 전제가 무너졌다.

## 1. 목표 / 가설

G3에서 (c) 학습 선택기는 기각됐지만, 그 근거였던 오라클 분석이 역으로 남긴 사실이 있다:
DB질의 골든에서 **오라클(문항별 최선) = 100% vs (b) 규칙 = 94.4%** — 즉 모델들의 오류가
**문항 단위로 비상관**이다. 선택기(사전 예측)가 아니라 **실행 후 결정론 신호로 합치는**
test-time 방법(투표/캐스케이드)이면 예측 없이 이 비상관을 회수할 수 있다.

- **H-E1a (캐스케이드):** 결정론 트리거(게이트 실패·실행 에러·빈 결과셋)에서만 2차 모델로
  재시도하면, 평균 호출 ~1.1×로 (b) 이상을 유지하며 실패 문항 일부를 회수한다.
- **H-E1b (교차모델 투표):** 2-of-3 결과셋 다수결은 골든에서 오라클(18/18)에 근접하고,
  (c)가 (b)를 이겼던 **합성 hard 분포(test 110)에서 ≥ 87.3%** (= (c) 최고치)를 학습 없이 달성한다.

핵심 논거: orthus의 DB질의는 sqlglot 게이트 + 실DB 실행이라는 **결정론 검증기**를 보유한
도메인이라, "선택은 결정론 코드가 한다"는 프로젝트 원칙과 정합인 test-time compute 적용처다.

## 2. 기존 코드/데이터 접점 (실측 심볼)

| 접점 | 위치 | 용도 |
|---|---|---|
| 모델별 SQL/결과셋 원자료 | `analysis/raw/t3_{solar,ax,exaone,baseline}.jsonl` (`sql`, `rows`, `row_count`, `gate_passed`, `status`, `ms`) | Phase A 오프라인 재생 입력 |
| 골든 정답 채점기 | `t3_gold.py` — `SPECS`(채점 대상 문항), `gold_numbers()`, `model_numbers()` (number-set match) | 문항별 정오 벡터 생성 |
| 합성 정오 라벨 | `train/data/labels_{solar,ax,exaone}.jsonl` + `train/data/split.json` (test split) | 합성 분포 투표 추정 |
| LLM-0콜 재생 전례 | `train/g3_gold.py` (골든 정오벡터 재생) | Phase A 방법론 재사용 |
| 워커 풀 | `pool.py` — `WorkerChat.complete()` (현재 `temperature=0` 고정), `build_pool()` | Phase B 라이브 실행 |
| 실행 하네스 | `harness.py::run_t3` (`query_structured(..., chat_model=chat)`) | Phase B 캐스케이드/투표 러너의 기반 |

## 3. 스코프

**In:** DB질의(NL→SQL) 태스크 한정. 골든(t3 채점 대상) + 합성 test split. 오프라인 재생 우선,
유의미할 때만 라이브. 캐스케이드 트리거는 결정론 신호만.

**Out:** 라우팅(규칙=오라클, 헤드룸 0 — 6.5), 지식응답(결과셋 동치 판정 불가 — judge 필요라
투표 비용 구조가 다름; E4 이후 별도 판단), 학습 선택기 일체(G3 기각 유지), 프로덕션 코드
변경(실험 격리; 채택 시 별도 제품 slice로).

## 4. 방법

### Phase A — 오프라인 재생 (신규 LLM 콜 0회)

1. **골든 정오 벡터:** `t3_gold` 채점을 모델별로 재실행해 문항×모델 정오 행렬 생성.
   오류 겹침 분석(어떤 문항에서 몇 모델이 동시에 틀리나)을 먼저 기록 — 이것이 투표 상한.
2. **투표 시뮬레이션:** 문항별로 3모델 `rows`→`model_numbers()` number-set을 비교.
   - 규칙 V1: 3모델 중 2개 이상 number-set 일치 → 그 답 채택. 전원 불일치 → (b) 배정(solar) 답 유지.
   - 규칙 V2(2모델 절약형): solar+exaone만 실행, 일치→채택, 불일치→ax를 tie-breaker로.
3. **캐스케이드 시뮬레이션:** 1차=solar, 트리거 발동 시 2차=exaone.
   트리거 후보를 각각 독립 평가: `gate_passed=False` / `status=error` / `row_count=0` /
   number-set이 `{0}` (S8 이모지 케이스형). 트리거별 발동률·회수·오발동(맞는 답을 버림) 집계.
4. **합성 분포 추정:** `labels_*.jsonl`(test split)로 "≥2모델 correct → 투표 정답" 추정치 계산.
   - **명시된 가정:** 정오 라벨만으로는 "두 모델이 같은 오답에 수렴"하는 경우를 못 잡는다.
     추정치 = 낙관 상한. 오답 수렴률은 골든 재생(rows 보유)에서 실측해 보정 계수로 사용.

### Phase B — 라이브 (Phase A 게이트 통과 시에만)

5. `pool.py`에 `temperature` 파라미터 추가 후 동일모델 self-consistency arm(solar k=3, temp 0.7)
   1회 실행 — 교차모델 투표와 "다양성의 출처"(모델 간 vs 샘플링 간) 비교.
6. 최우수 구성(투표 또는 캐스케이드)을 골든 전체 + 합성 test에 라이브 실행, 지연 실측.

## 5. 판정 기준 (사전 고정 — 실행 전 확정, 이후 변경 금지)

- **채택:** 골든 DB질의에서 (b)+1문항 이상(= 오라클 도달) **그리고** 합성 test ≥ 87.3%,
  **동시에** 오발동으로 인한 손실 0(맞던 문항을 틀리게 만들지 않음).
- **부분 채택(캐스케이드만):** 투표가 기준 미달이어도, 캐스케이드가 손실 0 + 평균 호출 ≤ 1.3×로
  회수 ≥ 1문항이면 "무해한 안전망"으로 기록.
- **기각:** 골든·합성 모두 이득 0 또는 오답 수렴률이 회수분을 상쇄 → "오류 비상관 가설 기각"으로
  보고서에 기록(그 자체가 G3 후속 발견).
- 예산 상한: 투표는 DB질의 한정 3×, 캐스케이드는 평균 ≤ 1.3× 호출. p95 지연 ≤ 단일 2배.

## 6. 대안 비교

| 옵션 | 장점 | 단점 | 판단 |
|---|---|---|---|
| A. 교차모델 2-of-3 투표 | 다양성 최대(오류 비상관 실측됨) | 3× 호출 | 주 실험 |
| B. 결정론 캐스케이드 | 평균 호출 ~1.1×, 손실 0 설계 가능 | 트리거 안 걸리는 "확신에 찬 오답"(S8형) 못 잡음 — 단 number-set `{0}` 트리거가 부분 커버 | 병행 (부분 채택 트랙) |
| C. 동일모델 self-consistency | 모델 1종 의존(운영 단순) | temp>0 다양성이 모델 간 다양성보다 약할 가능성; temperature 파라미터 작업 필요 | Phase B 보조 arm |
| D. 학습 reranker | — | G3에서 구조적 기각(헤드룸 1문항) | 제외 |

## 7. 리스크 / 불확실성

- **오답 수렴(correlated wrong):** 두 모델이 같은 잘못된 해석(예: 동일한 GROUP BY 과분해)으로
  같은 number-set을 낼 수 있음 → 투표가 오답을 "확정"함. Phase A에서 골든 rows로 실측이 1순위.
- **number-set 충돌:** 서로 다른(하나는 틀린) 질의가 우연히 같은 숫자집합을 낼 수 있음 —
  t3_gold 설계 한계 공유. 골든 문항 규모(≈18)에선 수동 스팟체크로 방어.
- **표본 소규모:** 골든 이득 최대 1문항이라 통계 검정 불가 — "골든 무손실 + 합성 이득"의
  2축 동시 판정으로 방어(G3와 동일한 판정 구조).
- **A.X RPS 3 / EXAONE 콜드스타트(TS3):** 라이브 투표 시 벽시계 지연이 최악 모델에 지배됨 —
  병렬 호출 + 타임아웃 시 2모델 결과로 판정하는 규칙을 사전 정의.

## 8. 게이트 (다음 단계 진입 조건)

1. **G-A→B:** Phase A에서 투표 추정 이득 > 0 **및** 오답 수렴률 < 회수율 → Phase B 진입.
   아니면 여기서 종료(기각 기록, 라이브 비용 0).
2. **G-B→보고서:** Phase B 실측이 §5 채택/부분 채택 기준 충족 → `competition-report.md`에
   "(d) test-time ensemble" 절 추가 + `experiment-log.md` 갱신.
