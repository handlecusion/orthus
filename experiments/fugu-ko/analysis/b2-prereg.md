# B2 사전선언 — 계약 이행 벤치마크 (Contract Compliance)

> 작성 2026-07-21 · 상태 **제안(미승인)** — 승인 시 **LOCKED**로 전환하고 이후 수정 금지.

## 0. 한 줄

**프로덕션 배선에 장착됐을 때 성능을 지배하는 것은 추론력인가, 출력 계약 이행인가.**

## 1. 이 실험의 출처 — 각주에 묻힌 관측

11모델 E2E에서 Claude Haiku 4.5는 **42.76%(62/145)로 최하위**였다. 그런데 표본 검사 결과
**펜스 안의 SQL·intent 내용 자체는 정확했다.** "마크다운 펜스 금지" 지시를 무시하고 모든 JSON을
` ```json `으로 감싸, 펜스-스트리핑이 없는 프로덕션 파서가 t3(0/28)·t9(1/32)를 전건 거부했을 뿐이다.

같은 계열 관측이 이미 여럿 있다.

| 관측 | 출처 |
|---|---|
| Haiku 4.5 — 펜스 불이행으로 t3·t9 전멸 | 11모델 E2E (2026-07-21) |
| A.X — 이메일 JSON 30중 13실패, tool-call 무시 | `model-orchestration.md` §12 |
| A.X/EXAONE — 값·이름 복사 손상(1.2B 한계), 앞공백 창작 48건 | `d7-results.md` §578 |
| gpt-4o-mini — 이모지·공백을 조용히 누락한 확신에 찬 오답(이모지 DB 27.3%) | D9, n=479 |

**추론력 벤치마크는 이 실패들을 못 잡는다.** 그런데 프로덕션에서는 이게 성능의 전부다.
B2는 이 축을 정식 측정 대상으로 승격한다.

## 2. 자백 — 이 실험이 기울어 있는 지점

1. **파서 정책이 점수를 만든다.** 펜스-스트리핑 한 줄을 넣으면 Haiku의 42.8%가 크게 달라진다.
   따라서 **엄격/관대 두 파서의 수치를 항상 병기한다**(§4). 한쪽만 보고하면 그건 파서 설정으로 이긴 것이다.
2. **우리 프롬프트는 우리 모델과 오래 붙어 다녔다.** few-shot과 지시문이 국내 모델의 습관에
   맞춰졌을 가능성이 있다. 그래서 §3의 주판정을 "누가 이겼나"가 아니라 **"분산이 어디서 큰가"**로 잡는다.
3. **계약 이행은 프롬프트로 상당 부분 고칠 수 있다.** 본 실험은 **현행 배선 기준 스냅샷**이며
   모델의 고정 능력치가 아니다.

## 3. 측정 대상과 주판정

### 3.1 위반 유형 7종 (각 n=40, 총 280문항)

| 코드 | 위반 유형 | 계약 근거 |
|---|---|---|
| C1 | 마크다운 펜스 감싸기 | 프로덕션 파서 bare JSON 요구 |
| C2 | JSON 스키마 이탈(필수 필드 누락/타입 불일치) | typed payload |
| C3 | enum 값 이탈(route·intent 7-way 등) | `router.classify_intent` |
| C4 | 필드 allowlist 위반(extra key) | `EmailDraftPayload` (P3.4d — SMTP/send/provider key 금지) |
| C5 | 빈 응답 / 설명문 혼입("네, 아래와 같습니다") | 결정론 파싱 |
| C6 | tool-call 지시 무시(호출 대신 산문 답변) | orthus-mcp tool 계약 |
| C7 | 값·이름 복사 손상(공백·이모지·특수문자 유실/창작) | 스키마 링킹 |

문항은 **기존 프로덕션 프롬프트를 그대로 쓰되 입력만 바꾼다**. 계약 위반을 유도하는 별도
적대 프롬프트를 만들지 않는다(그건 다른 실험이다).

### 3.2 지표

```text
strict_pass   현행 프로덕션 파서 통과율
lenient_pass  펜스 스트립 + 관대 JSON 복구를 적용한 통과율
recovery      lenient_pass − strict_pass      ← "배선만 고치면 살아나는 정도"
```

### 3.3 주판정 (결과 보기 전 고정)

**주장은 순위가 아니라 분산이다.** 같은 모델 집합에서

```text
Var_contract = 모델 간 strict_pass 의 분산
Var_accuracy = 모델 간 145문항 정확도의 분산   (기존 E2E 값 재사용)
```

**판정: `Var_contract > Var_accuracy` 인가** (bootstrap 10,000, seed 1234, 분산비 CI).

| 결과 | 문안 |
|---|---|
| CI 하한 > 1 | **"프로덕션에서는 계약 이행이 추론력보다 큰 변별 요인이다"** |
| CI가 1을 포함 | **"두 축의 변별력이 비슷하다"** — 주장 철회 |
| CI 상한 < 1 | **"정확도가 더 큰 변별 요인이다"** — 반대 결과 그대로 보고 |

이 판정은 **우리 모델이 1등인지와 무관하게 성립하거나 무너진다.** 의도적으로 그렇게 설계했다.

## 4. 반드시 함께 보고할 것

1. **strict / lenient 양쪽 표를 나란히.** 한쪽만 실린 표는 이 문서 위반이다.
2. **`recovery`가 큰 모델을 명시.** "이 모델은 능력이 아니라 배선 때문에 낮다"를 우리가 먼저 말한다.
3. **국내 모델의 실패도 동일 기준으로.** A.X의 C6(tool-call 무시)·C2(이메일 JSON)는 예상되는
   실패이며 **감추지 않는다**. 감추면 §3.3 주판정 자체가 오염된다.
4. **파서 개선 제안.** 측정으로 끝내지 않고, 펜스-스트리핑을 프로덕션에 넣을지 여부를
   **별도 결정 항목**으로 올린다(넣으면 관대 파서가 곧 현행이 되어 이 벤치마크의 기준선이 바뀐다).

## 5. 이 실험이 주장할 수 없는 것

1. **추론력 평가가 아니다.** Haiku 42.8%를 "Haiku가 약하다"로 읽어서는 안 된다.
2. **고정 능력치가 아니다.** 프롬프트 한 줄, 파서 한 줄로 뒤집힌다. 측정 시점의 배선 스냅샷이다.
3. **벤더 비교 근거로 쓰지 않는다.** 계약 이행률은 모델 버전마다 급변한다.
4. n=40/유형은 **유형별 세부 순위를 주장하기엔 작다.** 유형별 수치는 탐색 보고다.

## 6. 실행 메모

- 어댑터는 전부 동일 경로(`orthus/models/adapters/`)를 쓰고 모델별 후처리 분기를 넣지 않는다.
- 위반 유형 자동 분류기는 **결정론 규칙**으로 짠다(LLM 판정 0회). 분류 불가 케이스는
  `unclassified`로 남기고 비율을 보고한다.
- 문항 저자와 채점 규칙 저자를 분리하고, 저자는 모델 출력을 보기 전에 계약 규칙을 확정한다.
