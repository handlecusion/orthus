# M7 — Agentic Loop Bench · 사전등록 (prereg)

**등록일: 2026-07-23. 이 문서 작성·동결 시점까지 어떤 모델도 어떤 M7 과제에 대해서도 실행되지 않았다.**
과제·픽스처는 블라인드로 작성됐다(작성 중 모델 호출 0회).

## §1 등록 예측 (pre-registered prediction)

지금까지의 전 지표(B/D/E/T 시리즈)는 **프로덕션 파이프라인 조건** — LLM이 결정론
스캐폴드 안의 슬롯-필러인 조건 — 을 측정했고, 그 조건에서 국내 모델은 프론티어와
동률이었다. M7은 정반대 조건을 측정한다: LLM이 **자율 에이전트**(계획 → 도구 호출 →
관찰 → 회복 → 종료)로 동작하는 조건. orthus는 국내 모델에 대해 이 조건을 의도적으로
출하하지 않는다.

> **등록 예측: 자율 루프 조건에서는 프론티어(claude-sonnet-4-6)가 국내
> 모델(solar/exaone)을 이길 것이다.**

국내 패배는 기대되는, 서사적으로 유용한 결과다(자율성 대신 결정론 스캐폴드를 택한
아키텍처 정당화). 그러나 결과는 어느 쪽으로 나오든 그대로 보고한다 — 완화도 조작도
하지 않는다. 국내가 동률이면 그렇게 보고한다(그 경우 스캐폴드 정당화는 약해지고 모델
주장이 강해진다는 점까지 명시).

`golden/m7_tasks.json` — 20과제, 전부 단일 호출로는 성공 불가능한 다단계 과제.

  실행보다도 먼저, 카나리아 이전에 수행)
- `golden/m7_tasks.json` sha256 = `e366f9b34e126b7850bd055ccdb88b87f80e6f9a38ca8633f42789ec9e137a1a`

| 구성 | ID | 형태 |
|---|---|---|
| read-chain 8 | R1–R8 | 2–3홉 조회 사슬(보드→디렉터리, 회의록↔위키 대조, 메일+위키 결합 등) |
| read+write 8 | W1–W8 | 조회로 대상 해석 후 쓰기 도구로 종료 상태 생성(메일 초안·보드 태스크·캘린더 등록·위키 수정 후보) |

각 과제는 `max_turns=6`(전 과제 동일)과 결정론 완료 판정(`checks`)을 갖는다.

## §4 루프 프로토콜

- **단일 하네스** `m7_run.py`, 전 모델 동일 시스템 프롬프트(모델별 튜닝 없음), 동일
  14-도구 광고(조회 9 + 쓰기 4 + data_gaps), 프로덕션 `tools.py` 스펙 포맷.
  transport 2종: OpenAI-호환 function calling(멀티턴 tool role 피드백), Bedrock
  Converse(toolUse/toolResult — 프로덕션 `run_tool_loop`과 동일 메시지 형식).
- **도구 백엔드는 전부 결정론 스텁**(`m7_env.py` 픽스처 월드, 가상 회사 다온컴퍼니).
  실 DB(`orthus_r2`)를 쓰지 않은 이유: (a) 프로덕션 `wiki_ask`는 내부에 chat LLM을
  중첩해 루프 측정을 오염시킨다(검색 품질은 B3에서 이미 측정), (b) 픽스처 사실은
  전부 허구라 파라메트릭 추측으로 완료를 위장할 수 없다, (c) 종료 상태가 프로세스
  내에서 완전 검증 가능하다. `orthus_r2`/`orthus_flowbench_staging` 무접촉.
- **턴 정의**: 어시스턴트 응답 1회 = 1턴. 턴에 tool call이 있으면 전부 디스패치해
  결과를 피드백. tool call이 없는 응답 = 최종 답변(종료). 6턴째에도 tool call이면
  max_turns 실패.
- **온도**: 국내/기본 0 (B2 규칙), gpt-5.3은 미전송(벤더 강제), bedrock은 프로덕션
  설정값. max_tokens 1024(국내), bedrock/gpt-5.3은 프로덕션·벤더 기본.

## §5 완료 판정 (결정론 — judge 없음)

- read/recovery: 최종 답변이 동결된 gold 문자열 그룹(각 그룹은 허용 표기 대안 목록)을
  **전부** 포함(공백 정규화·대소문자 무시). gold 사실이 허구라 우연/사전지식 정답 불가.
- write: 환경 종료 상태 assert — 초안 수신자 이메일 정확 일치(+내용 키워드), 태스크
  담당자 정확 일치, 일정 날짜 정확 일치, 후보 slug 정확 일치.
- V3(정보 부재): 정직한 부정 답변 + 전화번호 패턴 부재 + 성공 도구 호출 ≥1
  (확인 없이 즉답 거절도 실패).
- 전 과제 공통: 성공 도구 호출 ≥1 (기본값; 도구 없이 산문 즉답은 완료 불가).

## §6 지표

모델별: **완료율(n=20)**, 완료 과제 평균 턴 수, **tool-call 포맷 실패 수**(알 수 없는
도구·필수 인자 누락·인자 JSON 파싱 불가), 정확 호출 수(LLM API 콜 수), 실패 단계
귀속. 귀속은 결정론 규칙(우선순위 순):

1. `api_error` — 벤더 API 오류로 런 미완(모델 추론과 분리해 별도 표기)
2. `no_tool_use` — 유효 tool call 0회로 산문 즉답(지어냄/무근거)
3. `max_turns` — 6턴 소진 시 tool call 잔존
4. `tool_format` — 미완료 + 포맷 실패가 해당 런 tool call의 ≥50%
5. `gave_up` — 도구는 썼으나 부정·포기 답변(V3 제외)
6. `wrong_path` — 그 외(잘못된 도구·인자·결과 오독)

## §7 주장하지 않을 것 (non-claims)

- **단일 하네스**다: 프롬프트를 모델별로 튜닝하지 않았고, 어느 모델에 더 맞는 표현일
  가능성을 배제하지 못한다.
- **n=20은 작다**: 완료율 차이의 유의성 검정은 보고하되(양측 McNemar 대응 비교),
  넓은 신뢰구간을 명시하고 순위 일반화를 주장하지 않는다.
- **인간 기준선 없음**: 절대 난이도 교정 없음.
- 픽스처 월드는 실 프로덕션 데이터가 아니다 — 도구 소음(검색 품질·DB 지연)이 없는
  낙관 조건이며, 실환경 완료율은 이보다 낮을 수 있다.
- ax 5과제 프로브는 순위 비교 대상이 아니다(기록 목적).
- 이 결과는 "자율 루프 일반"이 아니라 **이 도구 표면·이 과제 분포**에서의 결과다.

## §8 실행 규칙

- 실행 전 모델별 preflight 1콜(과금/인증 결함 조기 발견, 실패 시 그 모델 fail-stop).
- 본 실행 전 모델별 카나리아 2과제(R1, W1 — ax는 R1만) 후 0점이면 원인 조사(하네스
  결함 vs 모델 실패 구분) 뒤 전체 실행. 카나리아 런도 본 집계에 포함하지 않고
  전체 20과제를 새로 돈다(카나리아는 하네스 검증 전용).
- Bedrock 예산: 20과제 × ≤6턴 + 카나리아 ≈ ≤135콜. 정확 콜 수를 결과에 보고.
- raw 산출: `raw/m7_<model>.jsonl` (과제별 전체 트랜스크립트 + 종료 상태 스냅샷).
  채점은 별도 `m7_score.py` → `analysis/m7-results.md`.
- `.env` 무수정(프로세스 내 env만), 커밋 없음.
