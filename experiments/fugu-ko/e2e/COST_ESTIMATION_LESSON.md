# 비용 견적 교훈 — 카나리 토큰 외삽은 골든 확정 전에는 믿지 마라 (2026-07-29)

잔여 5종 본 실행(`remaining_run.py`, 33,229콜)에서 사전 견적 **$58.41** 대비 실제
**$77.31**(+32%)이 나와, 지시받은 $80 상한에 걸려 `claude-opus-4.8` 레인이 3,591/4,747에서
멈췄다. 더 나쁜 것은 **멈춘 위치가 무작위가 아니었다는 점**이다 — 작업 순서가 `(task, id)`
정렬이라 캡이 꼬리에서 걸렸고, 빠진 1,156건이 **wiki_qa 1,000건 전량 + synthesize 156건**이
됐다. 즉 예산 초과는 "조금 덜 채운 것"이 아니라 **judge 채점 대상 2종에서 최강 프론티어
비교를 통째로 못 하게 만드는 계통적 결손**을 만든다.

## 왜 낮게 나왔나

견적을 **골든 확정 전에** 카나리 몇 콜의 토큰으로 외삽했다. 그때 카나리가 쓴 입력은
더미/파일럿 문항이라 실제 골든보다 프롬프트가 훨씬 작았다:

- `wiki_qa` — 실제 근거는 5문단 평균 **929자**(p90 1,179자) + 프로덕션 시스템 프롬프트가
  긴 편이다. 카나리 관측 평균은 prompt 598토큰이었는데 이는 실제보다 확연히 작다.
- `synthesize` — freeze된 sub 본문이 평균 **870자**(p90 1,299자). 카나리 관측 567토큰은
  2조각짜리 짧은 더미에서 나온 값이다.
- 출력 토큰도 과소평가했다. `wiki_qa` 프롬프트는 "완결성"을 명시 요구해서 답이 길고,
  출력 단가가 입력의 5배인 모델(opus $25/1M, gpt $15/1M)에서는 이 오차가 그대로 증폭된다.

## 다음에 지킬 규칙

1. **골든이 확정된 뒤 실제 프롬프트로 견적을 다시 내라.** 카나리 단계의 외삽은 "배선이
   살아있나"를 보는 값이지 예산 근거가 아니다. 골든 확정 후에는 태스크·모델당 **실문항
   5~10건**을 실제로 돌려 토큰을 재고, 그 평균으로 재산정한 뒤 실행을 개시한다.
2. **입력 크기는 코드로 먼저 재라.** 골든/freeze 캐시에서 근거 문자열 길이를 집계하면
   (한국어 대략 2.5자≈1토큰) LLM을 한 번도 부르지 않고 prompt 토큰 하한을 얻는다.
   출력은 최소 300토큰, 추론형 모델은 최소 500토큰으로 가정하고 상한을 잡는다.
3. **캡은 레인별이 아니라 "완주 가능"으로 잡아라.** 레인 캡이 총예산의 단순 안분이면,
   비싼 레인이 정렬 꼬리(= 특정 태스크 전체)에서 잘려 계통적 결손을 만든다. 캡을 낮게
   잡아야 한다면 차라리 **태스크별로 나눠 실행**해(`--tasks`) 모든 모델이 같은 태스크를
   끝내게 하고, 그다음 태스크로 넘어간다 — 그러면 예산이 모자라도 결손이 "태스크 단위"라
   비교가 성립한다.
4. **예산 상한은 넘지 말고 보고하라.** 이번에 $77.31에서 멈추고 owner 승인을 받아
   $11.6을 추가한 절차가 정답이었다. 캡 도달은 실패가 아니라 설계된 정지다.
